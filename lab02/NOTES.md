# Лабораторная работа №2

## Состояния Git

### Рабочая папка

Рабочая папка — это файлы проекта, с которыми я сейчас работаю. Изменения в них ещё не обязательно сохранены в истории Git.

### Индекс

Индекс — это промежуточная область Git, в которую я добавляю изменения перед созданием коммита. Для добавления файлов в индекс используется команда `git add`.

### Коммит

Коммит — это сохранённое состояние проекта в истории Git. Каждый коммит содержит определённый набор изменений и сообщение, описывающее эти изменения.


## Git и GitHub

Git — это система контроля версий. Она работает локально на компьютере и позволяет хранить историю изменений проекта, создавать коммиты и работать с ветками.

GitHub — это интернет-сервис для хранения Git-репозиториев. Он позволяет публиковать проекты, совместно работать с другими людьми и хранить удалённую копию репозитория.

## Разница между git diff и git diff --staged

Команда `git diff` показывает изменения между рабочей папкой и индексом. То есть она показывает изменения, которые ещё не были добавлены командой `git add`.

Команда `git diff --staged` показывает изменения между индексом и последним коммитом. То есть она показывает, какие изменения войдут в следующий коммит.
## Использованные команды

`git status` показывает текущее состояние репозитория: изменённые файлы, файлы в индексе и файлы, которые Git пока не отслеживает.

`git diff` показывает изменения в рабочей папке, которые ещё не были добавлены в индекс.

`git diff --staged` показывает изменения, уже добавленные в индекс и подготовленные для следующего коммита.

## Ветки

Ветка в Git — это отдельное направление разработки проекта. Она позволяет вносить изменения независимо от основной ветки.

Когда в текущей ветке создаётся новый коммит, указатель этой ветки перемещается на новый коммит.

Слияние веток объединяет изменения из одной ветки с другой. После слияния изменения из дополнительной ветки становятся частью основной истории проекта.
